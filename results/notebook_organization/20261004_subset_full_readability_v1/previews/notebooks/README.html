Notebook workflows

Active workflows are separated by dataset directory and numbered consecutively:

  • Subset/: subset dataset under data/subset, notebooks 01–15.
  • Full/: full dataset under data/raw and data/processed, notebooks 01–03.
  • archive/: historical experiments, outside the active sequence.

Subset was previously called d1; Full was d2. Existing data files, saved runs and models retain their original _d1/_d2 identifiers so provenance still matches. The folder name identifies the notebook's dataset; keep the two branches' results and evaluation splits separate.

“Executed” means outputs are saved, not that a method is a final model. Image pilots reuse one inner validation split, while metadata out-of-fold (OOF) predictions combine held-out development folds. Neither replaces an independent reserved test. Opening saved outputs does not require training; running preparation or modelling cells can write files, as described in each notebook.

Metadata evaluation workflow (Subset)

If regenerating metadata results, run Subset/06_metadata_neural_network.ipynb, then Subset/08_metadata_robustness.ipynb. The first notebook evaluates three predeclared NN runs. The second uses training-only cutoff and calibration selection, patient-bootstrap confidence intervals, subgroup checks and a frozen spline model fitted without opening the reserved test labels.

See the plain-language methodology guide for why each step is needed, how it works and what its results can establish. The earlier 04/05 threshold examples are exploratory; use 08 for held-out evaluation of a training-selected cutoff. All development OOF results remain development evidence.

The dependency snapshot for 06/08 is requirements-metadata.txt. Run the notebooks with the project environment, for example:

.venv/Scripts/python.exe -m jupyter execute --inplace --timeout=900 notebooks/Subset/06_metadata_neural_network.ipynb
.venv/Scripts/python.exe -m jupyter execute --inplace --timeout=900 notebooks/Subset/08_metadata_robustness.ipynb

The later final-test script is scripts/evaluate_metadata_holdout.py; the guide explains its frozen-model and one-attempt controls. It has been tested with synthetic data, but the actual reserved test remains unevaluated.

Image pilot workflow (Subset)

Subset/09_image_b0_pilot.ipynb uses shared utilities and configs/image_model.yaml. The first pilot compares four B0 learning-rate/loss settings on one inner patient split, excluding outer fold 0 entirely. Its predictions are inner validation scores, not final OOF evidence. It does not read the reserved test.

See the image methodology and staged roadmap. The existing .venv has CUDA enabled; its dependency snapshot is requirements-image.txt. The original pilot training command is retained in its archived source snapshot. Current code changes must not bypass the historical manifest's source mismatch. The architecture experiment has its own runner:

.venv/Scripts/python.exe scripts/run_image_architecture.py --config configs/image_architecture_pilot.yaml --session-file results/image_d1_runs/architecture_pilot_3h_v1/session.json --resume

That command respects the supplied session deadline and training allowance; an expired session cannot silently allocate more time. Future resumption requires an explicitly allocated new session. Both image notebooks default to saved results. Six-epoch comparisons do not remove slower families from later work.

To save all result tables and figures using the explicitly selected environment:

.venv/Scripts/python.exe scripts/execute_image_notebook.py
.venv/Scripts/python.exe scripts/execute_image_notebook.py --notebook Subset/10_image_architecture_comparison.ipynb

The controlled augmentation utilities use configs/image_augmentation.yaml and scripts/run_image_conditions.py. Quality approval, source-compatible checkpoints and the fixed session deadline are mandatory. The current stronger profile remains blocked; a later safer profile requires a new declared experiment. CLAHE was not installed or trained because the complete safe A/B prerequisite was unavailable. Do not bypass the gate or extend an expired session silently.

Rebuild and execute the new saved-result reports without training:

.venv/Scripts/python.exe scripts/build_image_condition_notebooks.py --execute

Image uncertainty workflow (Subset)

Subset/13_image_uncertainty.ipynb selects an existing run and recipe explicitly. Its default is condition A of b0_augmentation_12e_v1, recipe lr3e5_sqrt, using the recorded best checkpoint at epoch 6. Supported DenseNet121 and ConvNeXt-Tiny recipes from architecture_pilot_3h_v1 can be selected explicitly; the notebook does not promote the highest pilot AP to a final architecture choice.

The notebook reconstructs the checkpoint's deterministic preparation and saved inner-validation membership, and checks that evaluation patients were absent from fitting. The current split has 1,834 images from 113 patients, including 33 malignant images, and excludes outer fold 0. These are inner-validation diagnostics, not full OOF or final-test results.

Run a short smoke check before the full default notebook:

.venv/Scripts/python.exe scripts/run_image_uncertainty.py --smoke
.venv/Scripts/python.exe scripts/execute_image_notebook.py --notebook Subset/13_image_uncertainty.ipynb

Alternative smoke checks require an explicit run, architecture and recipe:

.venv/Scripts/python.exe scripts/run_image_uncertainty.py --smoke --run-id architecture_pilot_3h_v1 --architecture densenet121 --recipe-id low_none
.venv/Scripts/python.exe scripts/run_image_uncertainty.py --smoke --run-id architecture_pilot_3h_v1 --architecture convnext_tiny --recipe-id low_none

Set the matching SOURCE_RUN, ARCHITECTURE and RECIPE_ID in the notebook before full alternative inference. Architecture recipe slots are low_none, low_sqrt, high_none and high_sqrt.

Each execution writes to a separate directory under results/image_uncertainty_runs, with raw predictions, summaries, figures, checks and provenance. It uses 30 dropout passes with only explicit dropout active, and separate identity/horizontal/vertical/both-flip TTA views. The referral comparisons use common deterministic scores and fractions for dropout SD, TTA SD, ordinary score, predictive entropy and repeated seeded random ranking, with paired patient-bootstrap intervals. Retained classification error uses the fixed raw cutoff 0.5; Brier error checks the score scale. These and the reliability checks are descriptive; no calibrator or referral threshold is fitted on pilot labels.

The historical archive retains the original code, execution and result paths. Use it to read the old three-epoch fold-0 experiment. New inference does not rewrite its results, checkpoints or training histories, and does not train, implement fusion or evaluate the reserved test.
